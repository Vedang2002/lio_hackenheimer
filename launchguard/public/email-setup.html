Google authorization is required. Downloading the code or signing into Gmail does not enable sending. The dashboard shows a recent check-in only after its private bridge is connected.

Connect using your Google OAuth client

The direct hosted worker reads and replies through the support account and updates this dashboard without an Apps Script project. Run node email-automation/connect-gmail.mjs "path-to-desktop-client.json" locally, open its Google consent link yourself, then securely configure the returned grant as Site secrets. No screen or browser control is needed.

After consent and activation, the hosted timer checks mail hourly. A client JSON alone does not grant mailbox access. Direct OAuth setup and troubleshooting

Alternative: connect using Apps Script

Copy these files into a Google Apps Script project owned by the support account. No Gmail password is stored in the app.

Worker codeConfigurationManifest
  1. Open Google Apps Script as support.hackenheimer@gmail.com. Create a project and copy the files.
  2. Show the manifest in Project Settings and replace it. Add the Gmail API service.
  3. Run verifyGmailConnection and complete Google consent yourself. Check that the log names the support account.
  4. Run startEmailAutomation. The one-minute timer now reads new eligible messages and sends priority receipts or configured approved answers. Historical inbox messages are excluded.
  5. Send a new test email from another address. Check Gmail Sent and run showEmailAutomationStatus. Run stopEmailAutomation to stop it.

Connect the agent work queue

To use answers approved on dashboard tasks and show confirmed reply status here, configure the private email bridge once. Until then, the worker operates independently using priority receipts and configuration rules.

  1. Set a strong EMAIL_BRIDGE_SECRET in the Site's secure runtime settings and redeploy.
  2. In the Google project's Script Properties, set LG_EMAIL_BRIDGE_SECRET to that value and LG_SITE_SERVICE_TOKEN to the Site's supported service-access token. Keep both private; never put them in code or Git.
  3. Keep task_queue mode enabled. Stop, run acceptEmailConfiguration, and restart the worker. Return to the dashboard and check for its heartbeat.
  4. Approve a public answer on a task using the exact customer email and a reference expected in their message. Exactly one match sends that answer; otherwise a receipt is sent.

Replies never automatically disclose internal stock, costs, or launch findings. Uncertain sends are held for reconciliation rather than repeated. Google quotas and configured daily limits apply.
